# Эмулятор оболочки — вариант 17

Практическая работа № 1 по дисциплине «Конфигурационное управление»,
ИКБО-15-25, РТУ МИРЭА. Реализация: C++17 и Qt 6 Widgets.
Требования варианта 17 находятся на страницах 56–58 предоставленного задания.

**Текущий этап: 1 — REPL.** Реализован графический прототип.
Переход к следующему этапу выполняется после одобрения текущего.

## Возможности

- Окно с заголовком «Эмулятор оболочки — VFS-17».
- Диалог с пользователем: поле ввода, Enter / кнопка «Выполнить», область вывода.
- Раскрытие переменных окружения реальной ОС: `$HOME`, `${HOME}`.
- Заглушки `ls` и `cd`, выводящие имя команды и список разобранных аргументов.
- Сообщения об неизвестной команде, неверных аргументах и ошибках синтаксиса.
- `exit` закрывает окно и завершает приложение.

Имя `VFS-17` на этапе 1 фиксировано. VFS ещё не загружается.
Заглушки не проверяют существование путей, не читают файлы и не меняют каталог.
Конфигурация, стартовые скрипты и CSV VFS относятся к последующим этапам.

## Сборка и запуск

Требуются компилятор C++17, CMake 3.21+ и Qt 6.5+ с модулями Core,
Widgets и Test. Сборка проверена на macOS с Apple Clang и Qt 6.10.0.

Быстрый запуск на macOS / Linux:

```sh
./run.sh
```

Скрипт собирает проект и запускает графическое приложение. Если `qt-cmake`
доступен в `PATH`, используется он; иначе скрипт ищет Qt в `~/Qt/*/macos`.
Для явного выбора установки:

```sh
QT_ROOT="$HOME/Qt/6.10.0/macos" ./run.sh
```

Настройки скрипта сборки: `QT_ROOT` — каталог установленного Qt,
`BUILD_DIR` — каталог сборки (по умолчанию `build`), `CMAKE_PREFIX_PATH` —
обычный путь поиска зависимостей CMake.
Это настройки сборки, а не параметры конфигурации эмулятора этапа 2.

Ручная сборка:

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH="$HOME/Qt/6.10.0/macos"
cmake --build build --parallel
./build/shell_emulator.app/Contents/MacOS/shell_emulator
```

На Linux запускайте `./build/shell_emulator`. На Windows укажите свою
установку Qt в `CMAKE_PREFIX_PATH`; для многоконфигурационной сборки:

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.10.0/msvc2022_64"
cmake --build build --config Debug --parallel
.\build\Debug\shell_emulator.exe
ctest --test-dir build -C Debug --output-on-failure
```

В Qt Creator откройте `CMakeLists.txt`, выберите комплект Qt 6 и запустите
цель `shell_emulator`.

## Тесты

```sh
./run.sh --test
```

Либо после ручной сборки:

```sh
ctest --test-dir build --output-on-failure
```

Три набора Qt Test проверяют парсер, команды и GUI. GUI-тесты вводят команды
через поле ввода, нажимают Enter и кнопку, проверяют восстановление диалога
после ошибок и закрытие окна по `exit`. CTest использует платформу `offscreen`.
Для сборки без тестов добавьте `-DBUILD_TESTING=OFF` при настройке CMake.

## Команды и правила парсера

| Команда | Аргументы | Результат этапа 1 |
| --- | --- | --- |
| `ls` | `[-a] [-l] [--] [путь ...]` | Имя и аргументы заглушки |
| `cd` | `[--] [путь]` | Имя и аргументы заглушки |
| `exit` | Без аргументов | Закрытие приложения |

`ls` принимает флаги `-a`, `-l`, их сочетания, например `-al`.
`--` завершает обработку флагов: `cd -- -folder` передаёт путь `-folder`.
Неизвестные флаги, более одного пути у `cd`, пустой путь и аргументы `exit`
считаются ошибками. Имена команд чувствительны к регистру.

Переменные берутся из окружения процесса через
[QProcessEnvironment::systemEnvironment](https://doc.qt.io/qt-6/qprocessenvironment.html#systemEnvironment).
Поддерживаются имена вида `[A-Za-z_][A-Za-z0-9_]*`.
В двойных кавычках переменные раскрываются с сохранением пробелов,
в одинарных кавычках текст остаётся буквальным. Без кавычек пробелы,
табуляция и перевод строки в значении переменной разделяют аргументы.
Неопределённая переменная раскрывается в пустую строку; без кавычек пустой
аргумент исчезает. Раскрытие не выполняется повторно для содержимого значения.

Обратная косая черта экранирует следующий символ вне кавычек.
В двойных кавычках она экранирует `$`, `"` и `\`; перед остальными символами
остаётся буквальной. В одинарных кавычках все символы буквальные.
Незакрытые кавычки, незавершённое экранирование и неверная запись `${...}`
вызывают ошибку без выполнения команды.

Пустой ввод игнорируется. Конвейеры, перенаправление, подстановка команд,
шаблоны файлов и специальные переменные оболочки на этом этапе не реализованы.

## Примеры использования

Команды вводятся в окне приложения:

```text
VFS-17:/$ ls
Заглушка: ls
Аргументы: []
VFS-17:/$ ls -al "my folder"
Заглушка: ls
Аргументы: ["-al","my folder"]
VFS-17:/$ cd "$HOME"
Заглушка: cd
Аргументы: ["/Users/your-user"]
VFS-17:/$ cd /one /two
Ошибка: неверные аргументы cd. Использование: cd [--] [путь].
VFS-17:/$ unknown
Ошибка: неизвестная команда «unknown».
```

Значение `$HOME` зависит от ОС и пользователя. Полный сценарий для защиты
этапа находится в [docs/stage1-demo.md](docs/stage1-demo.md).

## Структура и функции

| Файл | Назначение |
| --- | --- |
| `src/main.cpp` | `main`: создание QApplication и запуск цикла событий |
| `src/commandparser.*` | `CommandParser::parse`: разбор ввода и переменных |
| `src/shell.*` | `Shell::execute`: проверка команды и аргументов, результат |
| `src/mainwindow.*` | `MainWindow`: создание GUI; `submitCommand`: один шаг REPL |
| `tests/test_parser.cpp` | Кавычки, переменные, экранирование, ошибки синтаксиса |
| `tests/test_shell.cpp` | Заглушки, допустимые аргументы, ошибки, `exit` |
| `tests/test_gui.cpp` | Интерактивный диалог и завершение через окно |
| `run.sh` | Сборка, запуск, `--test`, `--build-only` |

Вспомогательные функции `isNameStart`, `isNameChar` и `variableName` проверяют
и извлекают имена переменных. `validArguments` проверяет аргументы,
`argumentError` формирует подсказку, `stubOutput` выводит список в JSON-нотации.
Результат парсера — список слов и текст ошибки. Результат команды — текст
вывода, признак ошибки и признак запроса завершения.
